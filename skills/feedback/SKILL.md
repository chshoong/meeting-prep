# 미팅 피드백 정리

허브 CLI는 `node "${CLAUDE_PLUGIN_ROOT}/hub/cli.js"`이다. `ok`가 false면 `error`를 전하고 멈춘다. `NO_HUB`면 `/meeting-prep:meeting-init`을 안내한다. 지금 바로 만들지 물어보고, 원하면 meeting-init 절차를 따른다.
명령이 `Cannot find package` 또는 `ERR_MODULE_NOT_FOUND`로 실패하면 `npm install --omit=dev --prefix "${CLAUDE_PLUGIN_ROOT}"`를 실행한 뒤 다시 시도한다.

## 1. 트랙 고르기

`log` 스킬과 같다: `$ARGUMENTS` 첫 단어가 트랙 이름이면 그것, 아니면 `resolve-track`, 그래도 모르면 목록에서 고르게 한다.

## 2. 피드백 원문 받기

`$ARGUMENTS`(트랙 이름을 뺀 나머지)나 바로 앞 메시지에서 찾는다.
- **파일 경로**(`.txt`, `.md`): Read 도구로 읽는다. 클로바노트 같은 녹음 변환 텍스트일 가능성이 높다.
- **노션 링크**: 노션 도구가 연결되어 있으면 그 페이지를 읽는다. 없으면 "노션이 연결되어 있지 않아요. 페이지 내용을 복사해서 붙여넣어 주세요."라고 요청한다.
- **붙여넣은 텍스트**: 그대로 쓴다.
- 아무것도 없으면 "피드백 메모나 녹음 텍스트를 붙여넣거나 파일 경로를 알려주세요."라고 요청한다.
- 음성 파일(`.m4a`, `.mp3` 등)이면 "음성 파일은 바로 읽을 수 없어요. 클로바노트 같은 앱에서 텍스트로 바꾼 뒤 알려주세요."라고 안내한다.

## 3. 분류하기

- **할 일**: 교수님이 다음 미팅까지 하라고 한 것. `#1`부터 번호를 붙인다.
- **지적 / 우려**: 문제점, 약점, 걱정하신 부분
- **아이디어 / 제안**: 당장 할 일은 아닌 제안, 장기 방향

녹음 텍스트에서 "~해보면 어때?", "~도 괜찮을 것 같은데"처럼 할 일인지 제안인지 애매한 말은 **따로 목록으로 모아** "이것들은 할 일로 넣을까요, 아이디어로 둘까요?"라고 묻는다.

## 4. 이월할 할 일

`status --track "<트랙>"`의 `open.dir`에서 `log.md`를 읽는다. "이번 사이클 할 일" 중 로그에 `→ 완료`로 기록되지 않은 항목이 있으면 목록을 보여주고 "이번 할 일로 이어서 넣을까요?"라고 묻는다. 넣기로 한 항목은 새 할 일 목록 뒤쪽에 `(이월)`을 붙여 번호를 이어 매긴다.

## 5. 미팅 날짜

`status`의 `open.name`이 날짜(`YYYY-MM-DD`)면 그 날짜가 미팅일이다. `next`면 오늘을 미팅일로 보고, 오늘이 아니면 알려달라고 한 번 묻는다.

## 6. 확인받기

아래 형식의 초안을 보여주고 확인받는다.

```
# 피드백 · <미팅 날짜>

## 할 일
- [ ] #1 <할 일>
- [ ] #2 <할 일>

## 지적 / 우려
- <내용>

## 아이디어 / 제안
- <내용>

## 원문
<붙여넣은 원문 전체, 또는 원문 파일 경로와 노션 링크>
```

- 할 일은 반드시 `- [ ] #번호 내용` 형식이어야 한다. 다음 사이클로 넘길 때 이 형식으로 읽는다.
- 빈 섹션은 `- 없음`으로 둔다.

## 7. 저장

1. Write 도구로 `<허브>/.tmp/feedback.md`에 쓴다.
2. `feedback-close --track "<트랙>" --file "<허브>/.tmp/feedback.md"`. 미팅일이 오늘이 아니고 `open.name`이 `next`였다면 `--date <YYYY-MM-DD>`를 붙인다. 사용자가 "10월 2일", "어제" 같이 답하면 YYYY-MM-DD 형식으로 바꿔서 쓴다.

## 8. 알려주기

- 닫은 사이클(`closed`)과 새로 연 사이클(`next`)
- 넘어간 할 일 목록(`todos`)
- "작업하면서 `/meeting-prep:log`로 기록하면, 다음 미팅 자료의 '지난 피드백 반영 현황'에 자동으로 들어가요."

# 미팅 피드백 정리

허브 CLI는 `node "${CLAUDE_PLUGIN_ROOT}/hub/cli.js"`이다. `ok`가 false면 `error`를 전하고 멈춘다.

## 0. 준비

`setup` 스킬의 "1. 준비"를 먼저 한다. 트랙이 여러 개면 피드백 내용으로 가장 알맞은 트랙을 고르고 "<트랙> 피드백으로 넣을게요"라고 알린다(되묻지 않는다. 틀리면 사용자가 정정한다).

## 1. 원문 받기

`$ARGUMENTS`나 바로 앞 메시지에서 찾는다.
- 파일 경로(`.txt`, `.md`): Read로 읽는다(녹음 변환 텍스트일 가능성이 높다).
- 노션 링크: 노션 도구가 있으면 읽고, 없으면 "노션이 연결되어 있지 않아요. 내용을 복사해서 붙여넣어 주세요."
- 음성 파일(`.m4a`, `.mp3` 등): "음성 파일은 바로 읽을 수 없어요. 클로바노트 같은 앱에서 텍스트로 바꾼 뒤 알려주세요."
- 아무것도 없으면: "피드백 메모나 녹음 텍스트를 붙여넣어 주세요."

## 2. 분류

- **할 일**: 다음 미팅까지 하라고 하신 것. `#1`부터 번호.
- **지적 / 우려**
- **아이디어 / 제안**: 당장 할 일은 아닌 것

## 3. 미팅 날짜

원문에 날짜가 있으면 그 날짜, 없으면 `status --track`의 `open.name`이 날짜면 그 날짜, 둘 다 없으면 오늘. 항상 `YYYY-MM-DD`로 바꾼다.

## 4. 확인은 한 번만, 필요할 때만

아래 중 **있는 것만** 한 메시지에 모아서 묻는다. 하나도 없으면 묻지 않고 5단계로 간다.
- 할 일인지 제안인지 애매한 말("~해보면 어때?"): "할 일로 넣을까요, 아이디어로 둘까요?"
- 이월 후보: `open.dir/log.md`의 "이번 사이클 할 일" 중 로그에 `→ 완료`가 없는 항목. "이어서 할 일로 넣을까요?" (넣으면 새 목록 뒤쪽에 `(이월)`을 붙여 번호를 이어 매긴다)

## 5. 저장

아래 형식으로 Write 도구를 써서 `<hubPath>/.tmp/feedback.md`에 쓴다(이미 있으면 먼저 Read).

```
# 피드백 · <YYYY-MM-DD>

## 할 일
- [ ] #1 <할 일>

## 지적 / 우려
- <내용>

## 아이디어 / 제안
- <내용>

## 원문
<원문 전체, 또는 파일 경로와 링크>
```

- 할 일은 반드시 `- [ ] #번호 내용` 형식이다. 빈 섹션은 `- 없음`.
- `feedback-close --track "<트랙>" --file "<hubPath>/.tmp/feedback.md" --date <YYYY-MM-DD>`

## 6. 알려주기

- 정리한 할 일·지적·아이디어 (짧게)
- "다음 미팅 사이클을 시작했어요. 작업하다 결과가 나오면 제가 기록을 제안할게요."
